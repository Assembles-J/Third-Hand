# AI 短线分析实现路线

## 产品边界

系统提供可核查的交易辅助，不承诺“明天必涨”，也不会自动下单。每个结论必须同时给出：已观察到的事实、系统解释、考虑条件、不做或失效条件、数据时间和覆盖范围。

## 用户只需提供的最少信息

第一阶段只要求可用本金；已有持仓可从截图识别后核对。交易计划、风险比例和最小交易单位是影响“可买数量”的必要信息，缺失时系统只显示观察，不编造精确数量。

## 当前已落地

1. `POST /v1/opportunity-scan/refresh`：优先通过 AKShare 的东方财富、再降级新浪全市场快照；两者失败时使用 Tushare 最近交易日日线兜底；全部失败时明确返回行情不可用。
2. `GET /v1/opportunity-scan`：从本地已有行情且至少 60 日日线的标的中筛选观察候选。
2. 交易台的“市场机会扫描”：用白话展示为什么观察、什么条件才考虑、什么情况不做/失效；明确观察强度不是上涨概率。
3. 未建立交易计划的标的只返回 `watch`，不会被包装成买入建议。
4. 扫描范围明确显示为本地缓存标的，避免把部分数据伪装成全市场扫描。

## 下一步纵向切片

1. 为全市场快照中的高优先级候选分批补齐日线，避免一次请求数千只股票的历史数据。
2. 按强势延续、低位启动、事件驱动、回避名单分组；每个标签都写出筛选规则和风险。
3. 点击候选进入股票详情，完成“观察 → 建立交易计划 → 风险约束下的数量建议 → 记录是否执行 → 模拟/实际复盘”的闭环。
4. 报告中首次出现术语时联动词库，并记录用户已查看词条；已理解的词不重复解释。
5. 用历史建议的触发、失效和后续走势校准筛选规则，所有模拟收益均与真实成交收益分开展示。

## 需要用户参与的节点

若要启用 Tushare 兜底，需要设置 `TUSHARE_TOKEN`。不配置时，系统仍会按 AKShare 的东方财富 → 新浪链路运行；两者失败会如实显示行情不可用。
